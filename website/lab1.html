📌 M365 Agent Builder vs Copilot Studio
เครื่องมือเหมาะกับ
M365 Agent Builderสร้าง Agent เร็ว จาก Description ง่ายๆ เชื่อม Knowledge จากเว็บได้ — ใช้ใน Lab นี้
Copilot Studioตั้งค่าละเอียดกว่า เชื่อม SharePoint/ไฟล์ได้ สร้าง Topics และ Evaluation ได้ — ใช้ใน Lab 2 เป็นต้นไป
💡 Grounding คืออะไร?

Grounding คือการ "ยึด" คำตอบของ Agent ไว้กับ Knowledge Source ที่กำหนด แทนที่จะปล่อยให้ Agent ตอบจากความรู้ทั่วไปของ AI เอง — เป็นหัวใจของ RAG ที่ทำให้คำตอบแม่นยำและลด Hallucination (การเดาคำตอบมั่ว) ทุก Lab ในคอร์สนี้จะเน้นเรื่อง Grounding เป็นหลัก

ขั้นตอนที่ 1–2: เปิด M365 Copilot และเริ่มสร้าง Agent

1

เปิด Microsoft 365 Copilot Chat

เปิด Browser ไปที่ https://m365.cloud.microsoft/chat แล้ว Login ด้วย Account ที่ได้รับ รอหน้า Chat โหลดให้เสร็จ

⚠️ ระวัง

⚠️ URL ต้องเป็น m365.cloud.microsoft/chat เท่านั้น — URL ที่คล้ายกันอย่าง copilot.cloud.microsoft เป็นคนละหน้าและจะไม่มีเมนู "New agent" ให้ใช้

หน้าจอ Microsoft 365 Copilot Chat หลัง Login สำเร็จ
2

เปิด Agent Builder

มองหาเมนู "Agents" ทางด้านซ้าย หรือกด "+ New agent" เพื่อเปิดหน้าสร้าง Agent ใหม่

หน้าจอ New agent — ช่อง Describe the agent you want to create

ขั้นตอนที่ 3–5: อธิบาย Agent และเพิ่ม Knowledge

3

ใส่คำอธิบาย Agent (Description)

พิมพ์คำอธิบายลงในช่อง Describe เช่น ต้องการ Agent สไตล์ครู ที่ตอบคำถามเรื่อง Copilot โดยอ้างอิงจากเอกสาร Microsoft เท่านั้น

พิมพ์ Description แล้วส่ง — AI จะช่วยตั้งชื่อและ Tone ให้อัตโนมัติ
📋 ตัวอย่าง Description — Copy ไปวางในช่อง Describe ได้เลย 
สร้าง Agent ชื่อ "Copilot Teacher" สไตล์ครูผู้สอนที่เป็นกันเอง ช่วยพนักงานเข้าใจความแตกต่างระหว่าง Microsoft 365 Copilot กับ Copilot Chat ตอบคำถามด้วยภาษาที่เข้าใจง่าย ไม่ใช้ศัพท์เทคนิคเกินจำเป็น

ถ้าถูกถามเรื่องนอกเหนือจาก Copilot ให้ตอบอย่างสุภาพว่าตอบได้เฉพาะเรื่องนี้ แล้วชวนกลับมาคุยเรื่อง Copilot

อ้างอิงคำตอบจากเอกสาร Microsoft ที่กำหนดไว้เท่านั้น ห้ามตอบจากความรู้ทั่วไป
💡 Tip

ยิ่งอธิบายละเอียดเท่าไหร่ Agent ยิ่งดีเท่านั้น — ใส่ให้ครบ 4 อย่างในคำอธิบายเดียว: (1) ชื่อ Agent ที่ต้องการ (2) Tone เช่น เป็นทางการ/เป็นกันเอง (3) ต้องทำอะไรเมื่อถูกถามนอกเรื่อง เช่น ปฏิเสธสุภาพและแนะกลับเข้าเรื่อง (4) วัตถุประสงค์ ของ Agent — ก่อนกด Create ให้ตรวจ Starter prompts ที่ระบบสร้างให้ในแท็บ Configure ด้วย ปรับแก้ให้ตรงคำถามที่ผู้ใช้จะถามบ่อยได้เลย

4

เพิ่ม Knowledge Source

ไปที่แท็บ Configure → Knowledge แล้วใส่ URL เว็บไซต์ที่ต้องการให้ Agent อ้างอิง เช่น เว็บ Documentation ขององค์กร

Knowledge Sources ถูกเพิ่มและ Index เสร็จแล้ว (Status: Ready)
5

เปิด "Only use specified sources"

เลื่อนหา Toggle นี้ในส่วน Knowledge แล้วเปิดเป็น On เพื่อบังคับให้ Agent ตอบจาก Knowledge ที่กำหนดเท่านั้น

เปิด Toggle "Only use specified sources" เป็น On
⚠️ ระวัง

ถ้าไม่เปิด Toggle นี้ Agent จะตอบจากความรู้ทั่วไปของ AI ด้วย อาจได้คำตอบที่ไม่ตรงกับเอกสารขององค์กรคุณ

ขั้นตอนที่ 6: สร้างและทดสอบ Agent

6

กด Create แล้วทดสอบถามคำถาม

ตรวจสอบการตั้งค่าในแท็บ Configure อีกครั้ง แล้วกด Create มุมขวาบน จากนั้นถามคำถามทดสอบในช่อง Chat

ทดสอบถามคำถาม — Agent ตอบพร้อมโทนที่กำหนดไว้
ตัวอย่างแบบเดียวกัน แต่คนละแผนก: IT Helpdesk Bot ตอบคำถาม Reset Password ด้วยขั้นตอนเดียวกับ Lab นี้ทุกประการ
📋 ตัวอย่าง Description สำหรับ IT — Copy ไปปรับใช้ได้ 
สร้าง Agent ชื่อ "IT Helpdesk Bot" ที่ช่วยพนักงานแก้ปัญหาเบื้องต้นเกี่ยวกับระบบ IT เช่น การ Reset Password และการขอสิทธิ์เข้าถึงระบบ ตอบด้วยขั้นตอนที่ทำตามได้ทันที เป็นข้อๆ สั้นกระชับ

ถ้าปัญหาซับซ้อนเกินกว่าจะแก้ด้วยขั้นตอนพื้นฐาน ให้แนะนำให้ติดต่อ IT Helpdesk พร้อมเบอร์ติดต่อ

อ้างอิงคำตอบจากคู่มือ IT ภายในองค์กรที่กำหนดไว้เท่านั้น
🎉 สำเร็จแล้ว!

คุณสร้าง RAG Agent ตัวแรกสำเร็จแล้ว! Agent นี้ตอบจาก Knowledge Source ที่คุณกำหนด ไม่ใช่ความรู้ทั่วไปของ AI

⚠️ ข้อผิดพลาดที่พบบ่อย

  • ลืมเปิด "Only use specified sources" → Agent ตอบนอกเรื่องได้
  • ใส่ URL หลายอันในข้อความเดียว → ระบบอาจรับแค่อันแรก ให้ใส่ทีละ URL
  • คำอธิบาย Agent สั้นเกินไป → ได้ Agent ที่ Tone ไม่ตรงกับที่ต้องการ ลองอธิบายให้ละเอียดขึ้น

🎯 ลองประยุกต์ใช้กับงานคุณ

📌 ไอเดีย Agent ตามแผนกงาน — เลือกที่ตรงกับคุณเป็นจุดเริ่มต้น
แผนกตัวอย่าง Agent ที่สร้างได้
Sales Engineerตอบสเปกสินค้า ราคา โปรโมชั่น จากแคตตาล็อกและใบเสนอราคา
Engineerตอบคู่มือซ่อมบำรุง สเปกเครื่องจักร ขั้นตอนขอใบอนุญาตทำงาน (Work Permit)
HRตอบนโยบายบริษัท สวัสดิการ วันลา จากคู่มือพนักงาน
Warehouseตอบขั้นตอนความปลอดภัย การจัดเก็บสินค้า อุปกรณ์ PPE ที่ต้องใช้ในแต่ละโซน
ITตอบ FAQ การใช้งานระบบภายใน ขั้นตอนขอสิทธิ์เข้าถึง (Access Request)
Programmerตอบ Coding Standard, API Documentation, ขั้นตอน Deploy ของทีม
Logisticตอบตารางเวลาขนส่ง นโยบายการจัดส่ง วิธีติดตามสถานะสินค้า
  • แผนกของคุณอยากได้ Agent ตอบคำถามเรื่องอะไร?
  • มีเว็บไซต์หรือ Documentation ภายในที่ใช้เป็น Knowledge Source ได้ไหม?
  • ลองเปลี่ยน Tone ของ Agent ให้เหมาะกับผู้ใช้งานของแผนกคุณ
