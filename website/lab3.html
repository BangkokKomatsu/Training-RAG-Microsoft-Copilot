📌 CARE Framework
องค์ประกอบใส่อะไร
C — ContextAgent คือใคร ทำงานให้ใคร อยู่ในสถานการณ์แบบไหน
A — Askสิ่งที่ต้องการให้ Agent ทำอย่างชัดเจน เช่น "ตอบคำถามจาก Knowledge เท่านั้น"
R — Rulesกฎ/ข้อจำกัดที่ต้องทำตาม เช่น ภาษาที่ใช้ รูปแบบคำตอบ Fallback message เมื่อไม่รู้คำตอบ
E — Examplesตัวอย่างคำถาม-คำตอบที่ดี เพื่อเป็น Reference ให้ AI

อ้างอิงจาก CAREful Prompts โดย Nielsen Norman Group (nngroup.com/articles/careful-prompts) — Framework เดียวกับที่ใช้ใน Microsoft Copilot Studio Labs ต้นฉบับ

💡 เทียบกับ Checklist "Role/Task/Scope/Rule/Tone" จาก Lab 1–2

Role + Task + Scope ≈ Context + Ask ของ CARE, Rule ≈ Rules ของ CARE — ส่วน Tone และ Example คือรายละเอียดเสริมที่ CARE ไม่ได้แยกเป็นหัวข้อของตัวเอง ใช้ Checklist 5 ส่วนเป็นตัวช่วยเขียนเร็วๆ ระหว่างลงมือ ส่วน CARE คือ Framework ทางการที่อ้างอิงได้เวลาต้องอธิบายให้คนอื่นเข้าใจ

ขั้นตอนที่ 1–2: ดูปัญหาของ Instructions แบบ BAD

1

เปิด Instructions ปัจจุบัน

ไปที่ Overview → Instructions → Edit ดู Instructions เดิมที่มักสั้นและกำกวมเกินไป

Instructions แบบ BAD — สั้นเกินไป ไม่ระบุ Tone หรือขอบเขต
2

ทดสอบและสังเกตปัญหา

ถามคำถามเดิมด้วย Instructions แบบ BAD สังเกตว่าคำตอบยาว วกวน ไม่ตรงประเด็น และไม่ได้อ้างอิง Knowledge

คำตอบจาก Instructions แบบ BAD — ยาว ไม่ตรงประเด็น ไม่ใช่ภาษาไทย

ขั้นตอนที่ 3–4: แก้ไขด้วย CARE Framework

3

เขียน Instructions ใหม่ด้วย CARE

ลบ Instructions เดิม แล้วเขียนใหม่ให้ครบทั้ง 4 องค์ประกอบ: Context, Ask, Rules, Examples

Instructions แบบ GOOD — ครบ Role/Task/Scope/Rule/Tone (CARE ครบทุกองค์ประกอบ)
📋 ตัวอย่าง Instructions (CARE) — Copy ไปวางแทน Instructions เดิมได้เลย 
Role: You are an HR assistant for Contoso.
Task: Answer employee questions about HR policy.
Scope: Answer ONLY from the provided HR policy documents.
Rule: If not found, say "ขออภัย ข้อมูลนี้ไม่อยู่ใน Policy กรุณาติดต่อ HR โดยตรง". Answer in Thai with max 3 bullet points.
Tone: Professional, concise, helpful — like a reliable HR colleague.
💡 Tip

เขียน Fallback message ให้ชัดเจนเสมอ เช่น "ถ้าไม่พบข้อมูล ให้บอกว่า..." เพื่อป้องกัน Agent เดาคำตอบ (Hallucinate)

ตัวอย่างแบบเดียวกัน แต่คนละแผนก: Code Review Bot สำหรับทีม Programmer — เขียน Instructions ด้วย CARE เหมือนกันแค่เปลี่ยนเนื้อหา
📋 ตัวอย่าง Instructions สำหรับ Programmer — Copy ไปปรับใช้ได้ 
Role: You are a senior developer assistant for the internal team.
Task: Review the code snippet the user pastes against our Coding Standard doc, and list violations with line references.
Scope: Only use the Coding Standard doc provided. If it doesn't cover something, say so instead of guessing.
Rule: Never rewrite the whole file — only point out issues. Keep each point to 1 line.
Tone: Direct, technical, peer-reviewer style — no fluff.
Example: "Line 12: ตัวแปรตั้งชื่อไม่สื่อความหมาย ควรใช้ camelCase"
4

Save และทดสอบคำถามเดิม

Save แล้วถามคำถามเดิมอีกครั้ง เปรียบเทียบกับคำตอบก่อนหน้า

คำตอบหลังปรับ Instructions — สั้น ตรงประเด็น เป็นภาษาไทย มีอ้างอิง

ขั้นตอนที่ 5: ทดสอบขอบเขต (Out-of-Scope)

5

ถามคำถามนอกเรื่อง

ทดสอบว่า Agent รู้จักปฏิเสธคำถามที่ไม่เกี่ยวข้องอย่างสุภาพหรือไม่ — นี่คือสัญญาณว่า Instructions ทำงานได้ผล

Agent ปฏิเสธคำถามนอกขอบเขตอย่างสุภาพ แทนที่จะพยายามตอบ
🎉 สำเร็จแล้ว!

Agent ของคุณตอบตรงประเด็น มี Tone ที่เหมาะสม และรู้ขอบเขตของตัวเองแล้ว! นี่คือขั้นตอนที่ทำให้ RAG Agent จาก "ใช้ได้" กลายเป็น "ใช้ดี"

⚠️ ข้อผิดพลาดที่พบบ่อย

  • เขียน Instructions ยาวเกินไปจนอ่านยาก → เน้นสั้น กระชับ แต่ครบ 4 องค์ประกอบ CARE
  • ลืมกำหนดภาษาที่ต้องการ → Agent อาจตอบเป็นภาษาอังกฤษปนไทย
  • ไม่มี Fallback message → Agent อาจเดาคำตอบเมื่อไม่รู้จริง (Hallucinate)

🎯 ลองประยุกต์ใช้กับงานคุณ

  • ลองเขียน Instructions ด้วย CARE Framework สำหรับ Use Case ของแผนกตัวเอง
  • ทดสอบว่า Agent ปฏิเสธคำถามเรื่องการเมืองหรือเรื่องส่วนตัวได้ไหม
