🔄 RAG Improvement Loop

แนวคิดหลักของ Lab นี้คือวงจร 4 ขั้นตอนที่ทำซ้ำได้เรื่อยๆ:

ขั้นตอนทำอะไร
1. Buildสร้าง Agent + Knowledge
2. Testถามคำถามด้วยตนเอง
3. Evaluateรัน Test Set ดู Pass Rate
4. Improveปรับ Knowledge หรือ Instructions แล้ววนกลับไป Test ใหม่

ขั้นตอนที่ 1–2: สร้าง Test Set

1

เปิด Evaluation Tab

ไปที่แท็บ Evaluation ในแถบนำทางด้านบนของ Agent

หน้า Evaluation ก่อนสร้าง Test Set
2

สร้าง Test Set แบบ Auto-Generate

+ New evaluation → Generate 10 questions → ตั้งชื่อ → Method: General Quality → Save

ฟอร์มสร้าง Test Set อัตโนมัติจาก Knowledge
📌 Test Set สร้างได้ 4 วิธี (Lab นี้ลองวิธีที่ 1)
วิธีเหมาะกับ
1. Auto-Generateให้ AI สร้างคำถามจาก Knowledge อัตโนมัติ — เริ่มต้นได้เร็วที่สุด ใช้ใน Lab นี้
2. Import จาก CSVเตรียมคำถาม+คำตอบที่คาดหวังไว้ล่วงหน้า สูงสุด 100 ข้อ/ไฟล์ — เหมาะกับ Test Set ขนาดใหญ่ หรือชุดคำถามที่ "ต้องตอบผิด" เช่น คำถามอันตราย (Adversarial Test)
3. Capture จาก Test Paneพิมพ์คุยกับ Agent ใน Test Pane ตามปกติ แล้วกด Evaluate เพื่อบันทึกบทสนทนานั้นเป็น Test Case ทันที — ได้ Expected Response จากคำตอบจริงของ Agent
4. พิมพ์เอง (Manual)ใส่คำถามที่ทีมงานรู้ว่าสำคัญที่สุดทีละข้อ — ใช้เสริม Test Set ที่มีอยู่

Test Set รันได้ทีละชุด (สูงสุด 100 คำถาม/ชุด) ผลลัพธ์เก็บไว้ให้ดูย้อนหลังได้ 89 วัน

ขั้นตอนที่ 3–4: Run และวิเคราะห์ผล

3

กด Evaluate และดูผลลัพธ์

รอ 3–5 นาที ระบบจะถามคำถามทั้ง 10 ข้อกับ Agent แล้วให้คะแนน Pass/Fail อัตโนมัติ

ผลการ Evaluate — Pass Rate 70%
📌 หมายเหตุ

Test Method คือวิธีตัดสิน Pass/Fail — "General Quality" ที่ใช้ใน Lab นี้ให้ AI ประเมินความถูกต้องโดยรวม เหมาะกับคำถามปลายเปิด นอกจากนี้ยังมี Exact/Keyword match (ตรวจคำตรงตัว), Similarity/Compare meaning (ตรวจความหมายใกล้เคียง), Capability use (ตรวจว่าเรียกใช้ Tool/Topic ที่ถูกต้องหรือไม่) และ Custom — เลือกใช้ตามลักษณะคำถามแต่ละชุด

4

วิเคราะห์คำถามที่ Fail

กดเข้าไปดูรายละเอียดคำถามที่ Fail เปรียบเทียบ Expected กับ Actual Response เพื่อหาสาเหตุ

รายละเอียดคำถามที่ Fail พร้อมสาเหตุ
💡 Tip

สาเหตุที่ Fail มักมาจาก 2 เรื่อง: (1) Knowledge ไม่มีข้อมูลนี้ → เพิ่มเอกสาร (2) Instructions ไม่ชัดเจน → ปรับ Instructions

💡 Tip

เปิด Activity map ในรายละเอียดคำถามที่ Fail เพื่อดูเส้นทางการทำงานทีละขั้นของ Agent — เห็นได้ว่า Agent ใช้ Knowledge Source ไหน เรียก Tool อะไร หรือเข้า Topic ไหนก่อนจะตอบ ช่วยระบุจุดที่ผิดพลาดได้เร็วกว่าอ่านแค่คำตอบสุดท้าย

ขั้นตอนที่ 5: ปรับปรุงและวัดผลซ้ำ

5

แก้ไขและ Evaluate อีกครั้ง

เพิ่มเอกสารหรือปรับ Instructions ตามที่วิเคราะห์ได้ แล้วรัน Evaluate ด้วย Test Set เดิมอีกครั้งเพื่อเปรียบเทียบ

Pass Rate เพิ่มขึ้นหลังปรับปรุง Agent
💡 Tip

ใช้ตัวเลือก "Compare with" เพื่อเทียบผลการรัน 2 ครั้ง — ลูกศรสีเขียวคือคำถามที่เพิ่งผ่านหลังแก้ไข ลูกศรสีแดงคือคำถามที่เคยผ่านแต่กลับมาล้มเหลว (Regression) ฟีเจอร์นี้ช่วยยืนยันว่าการแก้ไขไม่ได้ไปทำให้จุดอื่นแย่ลงโดยไม่ตั้งใจ

🎉 สำเร็จแล้ว!

คุณมีกระบวนการวัดและปรับปรุงคุณภาพ RAG Agent อย่างเป็นระบบแล้ว! เป้าหมายไม่ใช่ 100% แต่คือ Pass Rate ที่เพิ่มขึ้นทุกรอบ

⚠️ ข้อผิดพลาดที่พบบ่อย

  • รัน Evaluation ก่อน Knowledge จะ Ready → ผลลัพธ์ไม่แม่นยำ
  • คาดหวัง 100% Pass Rate ตั้งแต่รอบแรก → ในทางปฏิบัติต้องทำซ้ำหลายรอบ
  • ไม่บันทึกว่าปรับอะไรไปในแต่ละรอบ → เปรียบเทียบผลไม่ได้ว่าอะไรช่วยจริง

🎯 ลองประยุกต์ใช้กับงานคุณ

ตัวอย่าง: Work Permit Bot ของทีม Engineer — Fail ข้อ 4 บอกว่า Knowledge ยังไม่มีรายละเอียดเรื่อง Line Break Permit ต้องเพิ่มเอกสาร
  • ตั้งเป้า Pass Rate ของ Agent แผนกคุณไว้ที่เท่าไหร่?
  • ลองเพิ่มคำถามที่ผู้ใช้จริงมักถามเข้าไปใน Test Set ด้วยตัวเอง
